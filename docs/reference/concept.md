# concept — 芝刈りシミュレーター構想メモ

作成日時: 2026-11-11 04:54
更新日時: 2026-11-11 05:05

最初の構想をまとめたアイデア集。確定した内容は [goals.md](../plan/goals.md) と [plan.md](../plan/plan.md) に反映し、ここには選択肢や検討材料も含めて残す。

## 1. どんなものを作るか

ゴルフ場規模の広い芝地を、芝刈り機で刈っていくシミュレーター。

- 舞台はなだらかな山のような起伏のある地形。
- 刈る範囲は地形の勾配から決める。勾配で地形を区分けするアルゴリズムも自作する(7 章)。
- グラフィックは実写寄り。少しデフォルメの入った、いくらかミニチュアっぽいリアルを目指す(3.4 節)。
- カメラは物理カメラとして扱い、焦点距離、自動露出、被写界深度を持つ(6 章)。
- 手動モード: 自分で芝刈り機を運転して刈る。
- 自動モード: 経路アルゴリズムが芝刈り機を走らせ、それを眺める。
- 刈った場所は芝が短くなり、進行方向に芝目(倒れる向き)がつく。往復刈りをすると、明暗の縞(ストライプ)が現れる。

気持ちよさの中心は「刈り跡がきれいに残り、広い面が少しずつ整っていく様子」。ここが見た目として成立するかどうかが最重要。

## 2. 体験の柱

| 柱 | 内容 |
| --- | --- |
| 刈り跡の美しさ | 縞模様、ダイヤ柄、外周刈りの輪郭が、光の当たり方で浮かび上がる |
| 広さと起伏 | 数百 m 四方の丘陵を刈れる。斜面に沿って縞がうねる景色を見せる |
| 区分けが見える | 勾配から「刈れる範囲」が決まる過程と結果を、色分け表示で確認できる |
| 運転する手応え | 刈り幅、旋回半径、速度のある乗用機を操る。重ね幅や折り返しの上手下手が跡に出る |
| 眺める楽しさ | 自動走行をドローン視点や俯瞰で眺める。時間の早送りもできる |

## 3. 芝の表現(核になる技術)

### 3.1 芝状態マップ

芝の状態は「地面に貼った 2D テクスチャ」で持つ。1 テクセルが地面の小区画に対応する。

| チャンネル | 内容 |
| --- | --- |
| 高さ | 芝丈(刈ると刈高まで下がる) |
| 向き X / Z | 芝が倒れている方向の 2D ベクトル(刈った時の進行方向) |
| 鮮度 | 刈ってからの経過。刈りたての色味、刈りカス、再生長に使う |

- 更新は GPU 上で行う。毎フレーム、芝刈り機の刈刃(デッキ)の形を状態マップのレンダーターゲットに描き込む(スタンプ方式)。前フレーム位置から現フレーム位置までを帯として描けば、高速走行でも隙間ができない。
- 「現在の高さが刈高より高い場合だけ下げる」「向きは刃が通ったら上書き」というルールにする。
- 解像度の目安は 10〜12.5 cm / テクセル。2048² のタイル 1 枚で約 256 m 四方。
- ゴルフ場全体(1 km 四方級)は 1 枚では持てないので、タイル分割して芝のあるタイルだけ確保する。最初はタイル 1〜2 枚で足りる範囲から始める。
- 刈り残し率などの統計用に、CPU 側にも粗い格子(50 cm 程度)で被覆状況を持つ。GPU からの読み戻しを避けられる。

### 3.2 見た目

実際の芝の縞は、芝が倒れた向きによる光の反射の違いで生まれる。見る人から遠ざかる向きに倒れた芝は明るく、手前に倒れた芝は暗く見える。これをそのままシェーダーで再現する。

- 遠景〜中景: 地面のシェーダーだけで描く。状態マップの向きと視線・太陽方向から明暗を計算する。高さは色味と粗さに反映する。ゴルフ場規模の大半はこれで描くことになる。
- 近景: カメラ周辺だけ、インスタンシングで芝の葉を数十万本描く。頂点シェーダーで状態マップを参照し、葉の長さと倒れ方を決める。未刈り部分は長くて風に揺れ、刈った部分は短く揃って一方向に寝る。
- 近景と遠景の切り替わりが目立たないよう、距離でフェードする。
- 太陽を低めにすると縞が強く出る。時間帯(朝・夕)の設定は見栄えに直結する。

### 3.3 追加したい要素(後回しでよい)

- 刈りカスの粒子、刈りカスが列になって残る表現。
- 芝の再生長(時間を進めると伸び、芝目も徐々に戻る)。詳細は 6.3。
- 区分ごとの違い(区分によって初期の芝丈と刈高が異なる)。
- タイヤ跡、朝露。

### 3.4 絵作りの方向(ミニチュア風のリアル)

実写寄りの絵にする。そのうえで、よくできたジオラマや模型を撮影したような、少しデフォルメの入ったミニチュア感を加える。リアルタイムで動くゲームの絵として成立させるが、漫画的な様式化はしない。

参考にするのは「ユニクロカレンダー」(UNIQLO CALENDAR。サービスは終了している見込み)。実在の風景を高い位置から見下ろし、チルトシフト撮影とタイムラプスで模型のように見せていた映像、という理解で進める。そこから取り入れる要素:

- 高い位置からの見下ろしの構図。
- ピントの合う範囲が帯状に狭く、手前と奥が大きくぼける写り(6.2 のミニチュア倍率とティルト)。
- タイムラプス特有の、少しコマ落ちしたちょこまかした動き(6.3)。
- 実写より少し鮮やかな色。

実寸で作る方針:

- モデルと地形はすべて実寸で作る。単位は 1 = 1 m。芝刈り機の寸法、刈り幅、芝丈、地形の広さと勾配は現実の値を使う。
- ミニチュア感は、物を小さく作るのではなく、カメラ側(ミニチュア倍率、ティルト、見下ろしの構図)と控えめな形のデフォルメで出す。
- 実寸にしておくと、物理カメラの計算、勾配の閾値、走行速度、経路計画の数値がそのまま現実と対応する。

土台は実写寄り:

- 物理ベースの質感とライティング。太陽と空の明るさは現実に近い比率で扱い、HDR で描いてからトーンマッピングする。
- 広い地形に届く影(カスケードシャドウ)、接地感を出す環境遮蔽、大気による遠景のかすみ。
- 縞は 3.2 の反射の違いを基本にする。誇張は「見えにくいときに少し強める」程度の調整値として持つ。

ミニチュア感の出し方:

- 浅い被写界深度。高い位置から見下ろし、ピントの合う範囲を狭くすると模型のように見える。広い景色でこれを得るための仕組みは 6.2 を参照。
- 形のデフォルメは控えめに。芝刈り機は実機の構造を保ちつつ、タイヤや刈刃などの特徴をわずかに大きく、角を丸くして、精密な模型のような佇まいにする。
- 芝の葉は実物よりやや太く長めにする。模型の芝らしく見え、本数も抑えられる。
- 色は実写より少しだけ彩度とコントラストを上げ、整った印象にする。
- 木や小物は細部を整理し、塗装された模型のような清潔な質感にする。

描画負荷は上がるので、品質設定(影、被写界深度、芝の密度)を切り替えられるようにし、60 fps を目標にする。

状態マップによる仕組み(3.1)は変わらない。

## 4. 芝刈り機

### 4.1 機種の候補

| 機種 | 特徴 | 位置づけ |
| --- | --- | --- |
| 乗用フェアウェイモア(リール式・多連) | 刈り幅 2.5〜3.5 m、時速 10 km 前後。縞がきれいに出る | 最初に作る主役 |
| ゼロターンモア(ロータリー式) | その場旋回ができ、操作が軽快 | 追加候補 |
| グリーンモア | 刈り幅が狭く、刈高数 mm の精密作業 | 追加候補 |
| ロボット芝刈り機 | 小型で自律走行。眺める用途向き | 自動モードと相性がよい |

### 4.2 挙動

- 車両モデルは単純な運動学モデル(自転車モデル)で始める。必要なのは位置、向き、速度、操舵角、最小旋回半径。
- 刈刃の上げ下げ(折り返し時に上げる)、刈高の設定、刈刃の ON/OFF。
- 地形に沿わせる(高さと傾きを地形から取得する)。本格的な物理エンジンは当面使わない。
- 機種ごとに登れる勾配の上限を持つ。これが区分けの閾値になる(7.2)。
- 斜面では登りで遅く、下りで速くなる程度の簡単な影響を入れる。手動で上限を超える斜面に入ったときの扱い(進めない、滑る、警告のみ)は未決。
- 操作はキーボードとゲームパッドの両対応を想定。

## 5. 自動走行(経路アルゴリズム)

全域を漏れなく走る「カバレッジ経路計画」の問題になる。経路の生成と、経路への追従を分けて作る。

### 5.1 経路パターン

| パターン | 内容 |
| --- | --- |
| 往復刈り(ボストロフェドン) | 平行な直線を往復する。基本形。縞の角度を指定できる |
| 外周刈り + 往復 | 先に外周を数周して旋回用の枕地を作り、内側を往復する。実作業に近い |
| 渦巻き(等高線状) | 外周から内側へオフセットしながら回る |
| 二方向刈り | 角度を変えて 2 回刈り、チェッカーやダイヤ柄を作る |
| ランダムバウンス | 境界に当たるたびに向きを変える。ロボット芝刈り機の古典的な方式で、効率の比較対象になる |

### 5.2 必要な処理

- 刈る領域は多角形(穴あり)で表す。勾配による区分け(7.2)の出力をそのまま入力にする。急斜面や木、池は穴になる。
- 縞の向きは区分ごとに決める。斜面では等高線に沿って走る(横切る)か、上下に走るかを選べるようにし、斜面方位から自動で決める方式も用意する。
- 複雑な形や障害物がある領域は、セル分解(ボストロフェドン分解)で単純な領域に分け、巡回順を決める。
- 折り返しは最小旋回半径を考慮する。U ターン、Ω ターン、切り返しターン、1 列飛ばしの順序などを選べるようにする。
- 追従制御は Pure Pursuit から始める。
- 経路は予定線として地面に表示できるようにする。アルゴリズムの違いが見て分かることがこのモードの面白さになる。

### 5.3 統計

刈り済み面積の割合、走行距離、所要時間、重複して刈った割合を表示する。アルゴリズム同士や、手動と自動の比較ができる。

## 6. カメラと眺め方

### 6.1 視点

- 追従カメラ(機体の後方)、運転席視点、俯瞰(真上)、ドローン(自由移動・周回)。
- 自動モード用に、カメラを自動で切り替えるシネマティック表示。視点ごとに焦点距離や絞りの初期値を変える(俯瞰は望遠で浅いピント、運転席は広角で深いピントなど)。

### 6.2 物理カメラ

カメラは画角を直接指定せず、実際のカメラと同じ設定値で扱う。

| 設定 | 内容 |
| --- | --- |
| センサーサイズ | 既定は 35 mm フルサイズ(36 × 24 mm)。画角と被写界深度の基準になる |
| 焦点距離(mm) | 画角を決める。ズームはこの値を変える |
| 絞り(F 値) | 被写界深度と露出に効く |
| シャッター速度 | 露出に効く。将来モーションブラーを入れる場合はその量にも使う |
| ISO 感度 | 露出に効く |
| ピント距離 | 手動、または自動(オートフォーカス) |
| 露出補正(EV) | 自動露出の狙いを明るめ・暗めにずらす |

露出:

- 光源は現実に近い明るさの単位で設定する。絞り・シャッター速度・ISO から露出値(EV)を求め、HDR の描画結果に掛けてからトーンマッピングする。
- 自動露出: 画面の平均輝度(対数平均)を測り、適正な明るさになるよう露出を決める。測光は中央重点を基本にする。急に変わらないよう、時間をかけて追従させる。
- 露出モードは、自動、絞り優先(絞りを固定して残りを自動)、手動を用意する。
- 芝は画面の大半を占めるので、自動露出が刈り跡の明暗を打ち消さないかを確認する(縞そのものは画面内の相対差なので残るはずだが、未刈りと刈り済みの面積比で全体の明るさが揺れる可能性がある)。

被写界深度:

- 焦点距離、F 値、ピント距離、センサーサイズから、距離ごとのぼけの大きさ(錯乱円)を計算し、深度バッファを使ったポストエフェクトでぼかす。
- オートフォーカス: 芝刈り機に合わせる方式と、画面中央の距離に合わせる方式を用意する。ピントは滑らかに移動させる。
- ミニチュア倍率(採用): 世界は実寸で作るので、そのままでは数百 m 先の景色はほとんどぼけない。ぼけの計算のときだけ距離を縮める倍率(例: 1/20〜1/100)を設け、模型を接写したような浅いピントを得る。倍率 1 なら実寸どおりの写りになる。視点ごとに初期値を持たせ(俯瞰やドローンは強め、運転席は実寸)、設定パネルで変えられるようにする。
- ティルト: ピント面を傾ける(チルトシフトレンズ相当)。見下ろしの構図で、帯状にピントが合う絵を作れる。参考にする映像の写りに直結するので、ミニチュア倍率と合わせて実装する。

レンズらしさ(控えめに、個別に切り替え可能):

- 周辺減光、ブルーム、わずかな色収差、フィルムグレイン。

UI:

- カメラ設定パネルで各値を操作できるようにする。スクリーンショット保存(写真モード)とも相性がよい。
### 6.3 時間

- 時間の早送り(2 倍〜数十倍)。早送り中も刈り跡の更新が破綻しないよう、シミュレーションは固定時間刻みで進める。

タイムラプス表現(後の段階で実装):

- 単なる早送りではなく、一定間隔で撮った写真をつなげたような見え方にする。数十倍〜数百倍の速さで、芝刈り機がちょこまかと動き、刈り跡がみるみる広がる。
- コマ落ち感: 画面の更新をあえて間引き(例: 毎秒 10〜15 コマ相当)、1 コマごとに動きが飛ぶようにする。滑らかな早送りとの切り替え式にする。
- 時間とともに変わるものを入れると効果が出る。太陽の移動と影の伸び縮み、雲の影が地面を流れる様子、空の色の変化。
- 自動露出はタイムラプス中もちらつかないよう、追従をゆっくりにする。
- 高倍速では 1 コマの間に芝刈り機が長い距離を進む。刈り跡の描き込みは、その間の走行経路をまとめて処理できるようにしておく(3.1 の帯描画を経路全体に拡張する)。

芝の再生長(後の段階で実装):

- 時間が進むと芝丈が伸び、芝目も徐々に立ち上がって縞が薄れていく。状態マップの全面を一定間隔で更新する処理として作る。
- タイムラプスと組み合わせると、刈る → 伸びる → また刈る、という繰り返しを眺められる。
- 状態マップの「鮮度」は、この用途のために最初から確保しておく。

## 7. コースと地形

### 7.1 地形

- なだらかな山のような起伏のある地形を対象にする。全体が芝で覆われた丘陵で、勾配によって刈る所と刈らない所が分かれる。
- 地形は高さマップで持つ。解像度の目安は 1 m / 格子(500 m 四方で 500²)。
- 作り方は 2 通り用意する。
  - 手続き生成: 低周波のノイズを重ねて丘を作る。シード値で再現でき、区分けアルゴリズムの試験に使いやすい。最初はこちら。
  - Blender で造形して高さマップを書き出す。見せたい景色を作り込む段階で使う。
- 芝状態マップは真上からの投影で地形に貼る。なだらかな斜面なら歪みは問題にならない。
- 刈り跡の試作(M1)だけは平坦な地面で行い、すぐ起伏に移る。

### 7.2 勾配による区分けアルゴリズム

高さマップから「どこを、どの機種で刈るか」を自動で決める。描画に依存しない純粋なロジックとして作り、単体テストする。

処理の流れ:

1. 平滑化: 高さマップを機体の大きさ程度(2〜3 m)でぼかす。機体より小さい凹凸で区分が荒れるのを防ぐ。
2. 勾配の計算: 各格子で高さの差分から傾斜角と斜面方位(下る向き)を求める。
3. 分類: 傾斜角を閾値で区分する。閾値は機種の登坂上限から決める。境界のぎざぎざを抑えるため、閾値に幅を持たせる(ヒステリシス)。
4. 整形: 刈り幅より細い帯や小さな飛び地は刈れないので、モルフォロジー処理(収縮と膨張)で取り除く。小さな穴は埋める。最小面積に満たない領域は隣の区分に吸収する。
5. 連結領域の抽出: 同じ区分でつながった格子をまとめ、領域ごとに番号を振る。
6. 到達可能性の確認: 開始地点から、機体が走れる勾配の所だけを通ってたどり着けるかを調べる。たどり着けない領域は「孤立」として区別する。
7. 輪郭の抽出: 領域の境界を多角形にし(マーチングスクエア)、頂点を間引いて滑らかにする。穴も多角形として持つ。
8. 出力: 区分、面積、平均勾配、代表的な斜面方位を持つ多角形の一覧。これを経路計画(5 章)に渡す。

区分の初期案(数値は仮。実機の目安をもとに調整する):

| 区分 | 傾斜角 | 扱い |
| --- | --- | --- |
| 平地〜緩斜面 | 0〜15° | 乗用機で刈る。主な対象 |
| 斜面 | 15〜30° | 斜面用の機種(ロボットやラジコン式)で刈る。乗用機は入らない |
| 急斜面 | 30° 以上 | 刈らない。長い芝のまま残す |

発展案:

- 斜面方位でさらに分割し、領域ごとに縞の向きを変える。丘を巻くような縞ができる。
- 走る向きを考慮する。同じ斜面でも、横切るときと上下に走るときで上限が違う。
- 曲率(尾根、谷)を使い、尾根線や谷線を区分の境界に使う。
- 区分の閾値を画面上で動かし、結果がその場で変わる様子を見せる。

表示:

- 区分を色分けして地形に重ねる表示モードを用意する。勾配そのものの色表示、斜面方位の表示も切り替えられるようにする。調整用であると同時に、見て楽しい要素にもなる。

## 8. Blender の使いどころ

- 芝刈り機のモデル(車体、リール、タイヤを別オブジェクトにして回転させる)。実機の構造を保った物理ベースの質感で、精密な模型のように少しだけデフォルメする(3.4)。
- 地形の造形と、高さマップの書き出し。
- 木、岩、柵、小屋などの小物。
- すべて実寸で作る。Blender の単位はメートル、1 単位 = 1 m とし、書き出し時に拡大縮小しない。
- 受け渡し形式は glTF(.glb)。書き出しは Blender の Python スクリプトで自動化し、ソースの .blend と書き出し結果を分けて管理する。
- 芝そのものは Blender で作らず、シェーダーとインスタンシングで描く。

## 9. 技術構成の案

| 項目 | 案 | 理由 |
| --- | --- | --- |
| アプリ枠 | Electron | 希望どおり。ローカルファイルの扱いが楽 |
| 描画 | Three.js(WebGL2) | レンダーターゲット、インスタンシング、glTF 読み込みが揃っている。生の WebGL より大幅に早く作れる |
| 言語 | TypeScript | 経路計画など計算ロジックが多いため型が欲しい |
| ビルド | Vite(electron-vite) | 開発時の再読み込みが速い |
| UI | 最小限の HTML/CSS + 調整用パネル(lil-gui など) | 序盤はパラメーター調整が中心 |
| 描画の後処理 | HDR 描画 + ポストエフェクト(露出、トーンマッピング、被写界深度、ブルームなど) | 物理カメラの実現に必要。自作か既存ライブラリかは M1 で決める |
| テスト | Vitest | 経路計画や被覆計算は描画と切り離して単体テストする |

構成上の方針:

- シミュレーション(車両、経路計画、被覆計算)は描画に依存しない純粋なロジックとして分離する。
- 状態マップに必要な浮動小数点レンダーターゲットは WebGL2 で使える。精度が足りる範囲では 8 bit テクスチャを優先する。
- WebGPU への移行は当面考えない。

## 10. 技術的な難所

1. 縞の見え方。シェーダーの明暗モデルが弱いと、このシミュレーターの魅力が出ない。最初に試作して確かめる。
2. 近景の芝の本数と描画負荷。カメラ周辺に限定した配置と LOD が必要。
3. 広さと状態マップの解像度の両立(タイル分割)。
4. 区分けで得られる複雑な形の領域に対する経路計画と折り返し。
5. 早送り時の安定性。
6. 区分けの結果が自然に見えること。閾値どおりに切るだけでは境界が荒れ、細切れの領域ができる。整形の加減が要になる。
7. 物理カメラ一式の描画負荷と調整。HDR、自動露出、被写界深度はポストエフェクトの段数が増える。被写界深度は芝の葉のような細かい形状の輪郭で破綻しやすい。
8. 現実に近い明るさの単位で光を扱うこと。露出の計算と整合させる必要があり、途中から導入すると全体の調整をやり直すことになるので、早い段階(M1)で入れる。

## 11. 未決事項

- 方向性: リラックスして眺める寄りか、作業の正確さを競うゲーム寄りか。
- 最終的な広さ: 500 m 四方程度で十分か、1 km 級まで目指すか。
- 最初の機種はフェアウェイモアでよいか。
- 区分の数と閾値。斜面用の機種を実際に登場させるか、斜面は「刈らない」だけにするか。
- 手動で上限を超える斜面に入ったときの扱い。
- デフォルメの度合い(参考はユニクロカレンダーに決定。実装しながら調整する)。
- ミニチュア倍率の具体的な既定値(採用は決定。視点ごとに初期値を持たせる案で進め、M5 で調整する)。
- ポストエフェクトを自作するか、既存ライブラリ(pmndrs の postprocessing など)を使うか。M1 で試して決める。
- セーブ(刈り跡の保存と再開)が必要か。
- 音(エンジン音、刈刃の音、環境音)をどの段階で入れるか。
